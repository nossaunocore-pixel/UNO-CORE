## TIPOS DE CONTRIBUIÇÃO

### 1. CÓDIGO

Qualquer adição, correção, melhoria de funcionalidade.

**Antes de enviar:**
- [ ] Leu os Volumes relevantes?
- [ ] O código está documentado?
- [ ] Há testes?
- [ ] Segue os padrões de estilo?
- [ ] É compatível com os princípios da Uno?

**O commit deve incluir:**
```
Tipo: Feature/Fix/Docs/Refactor

Descrição breve e clara.

Por que isto foi feito?
Como isto se alinha com a Missão?
Quais foram as alternativas consideradas?

Volume de Referência: (qual volume justifica isto)
```

### 2. DOCUMENTAÇÃO

Explicar, esclarecer, adicionar exemplos.

**Documentação é tão importante quanto código.**

Toda decisão deve ter justificativa registrada.  
Todo erro deve gerar aprendizado documentado.  
Toda lição deve ser compartilhada.

### 3. AUDITORIAS E QUESTÕES

"Isto está alinhado com a Missão?"  
"Por que foi decidido assim?"  
"Há uma forma mais honesta?"

**Questionar é contribuir.**

Não com crítica destrutiva. Com curiosidade honesta.

### 4. ENSINO E MENTORIA

Ensinar a outros como a Uno funciona.  
Ajudar novos contribuidores.  
Preservar conhecimento.

## PROCESSO DE CONTRIBUIÇÃO

### PASSO 1: PROPOSTA

Abra uma issue ou discussão explicando:

- **O que** você quer fazer
- **Por que** isto é importante
- **Como** você planeja fazer
- **Qual Volume** justifica isto

**Não comece a trabalhar sem concordância inicial.**

### PASSO 2: DISCUSSÃO

A comunidade comenta, questiona, sugere.

- Seja aberto a feedback
- Explique seu pensamento
- Reconheça alternativas
- Seja humilde

### PASSO 3: IMPLEMENTAÇÃO

Se aprovado, comece o trabalho.

- Código limpo, documentado
- Testes abrangentes
- Explicação clara
- Alinhamento com princípios

### PASSO 4: REVISÃO

Um ou mais revisores examina:

- Qualidade técnica
- Alinhamento com princípios
- Impacto no bem comum
- Transparência

**Revisão não é crítica. É cuidado com a Missão.**

### PASSO 5: INTEGRAÇÃO

Quando aprovado:

- Merge no repositório
- Commit registrado permanentemente
- Seu nome na contribuição
- Aprendizado extraído e documentado

## PADRÕES DE CONTRIBUIÇÃO

### CÓDIGO

- [ ] Linguagem clara, variáveis com significado
- [ ] Comentários explicam PORQUÊ, não O QUÊ
- [ ] Funções pequenas, com responsabilidade única
- [ ] Testes abrangentes (sim, testes são obrigatórios)
- [ ] Sem hardcodes, sem "gambiarras"
- [ ] Alinhado com a Arquitetura Oficial (Volume 2)

### DOCUMENTAÇÃO

- [ ] Claro, em linguagem simples
- [ ] Exemplos práticos
- [ ] Links para contexto
- [ ] Explica PORQUÊ, não só O QUÊ
- [ ] Atualizado e verificado
- [ ] Em português, por enquanto

### COMMITS

```
tipo: assunto breve (imperativo)

Descrição mais detalhada se necessário.
Por que esta mudança?
Qual o contexto?
Como isto se alinha com a Missão?

Referências: #123, Volume X
```

**Tipos de commit:**
- `feat:` → Nova funcionalidade
- `fix:` → Correção de bug
- `docs:` → Documentação
- `refactor:` → Reorganização sem mudança funcional
- `test:` → Testes
- `chore:` → Manutenção

## RESOLVENDO CONFLITOS

### Discordo de uma decisão

1. **Pergunte** — "Por que foi decidido assim?"
2. **Estude** — Entenda o contexto e os princípios
3. **Proponha** — "Posso sugerir uma alternativa?"
4. **Ouça** — Compreenda por que sua ideia foi recusada
5. **Aceite** — Ou escale para revisão formal

### Encontro um erro

1. **Registre** — Abra uma issue clara
2. **Seja respeitoso** — Não ataque o autor
3. **Proponha solução** — "Posso ajudar a corrigir?"
4. **Trabalhe junto** — Colabore para resolver

### Tem um conflito pessoal

1. **Pause** — Não discuta irritado
2. **Fale em privado** — Não em público
3. **Busque entender** — Qual é a verdadeira diferença?
4. **Encontre comum** — Onde concordamos?
5. **Escalpe se necessário** — Para mediadores

**Conflitos são oportunidades de aprender.**

## COMO REPORTAR PROBLEMAS

### Encontrou um BUG?

1. Abra uma issue com:
   - Descrição clara do problema
   - Como reproduzir
   - Resultado esperado
   - Resultado obtido
   - Ambiente (versão, SO, etc)

2. Seja respeitoso — Quem escreveu fez seu melhor
3. Ofereça-se para ajudar a corrigir

### Encontrou uma VIOLAÇÃO DE PRINCÍPIOS?

1. Abra uma issue com a tag `ethics` ou `mission-alignment`
2. Explique qual princípio está sendo violado
3. Cite o Volume relevante
4. Proponha como corrigir

**Isto será revisado com prioridade.**

### Quer sugerir uma MELHORIA?

1. Abra uma discussão (não issue)
2. Explique a ideia
3. Por que melhoraria as coisas?
4. Qual o impacto?
5. Aguarde feedback antes de trabalhar
